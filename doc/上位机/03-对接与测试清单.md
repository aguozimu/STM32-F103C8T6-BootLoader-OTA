# 上位机对接与测试清单

> 协议版本：`OTA-PROTO-1.0`　完整规范：`01-通讯协议完整规范.md`

## 一、对接前检查

- [ ] 已实现 STM32F1 硬件 CRC32，参数为 `0x04C11DB7 / 0xFFFFFFFF / xorout=0`。
- [ ] 已把类型字段固定为 6 字节 ASCII，没有追加 `\0`。
- [ ] 已把帧固定为 16 字节，并保存每个业务帧的 CRC32。
- [ ] 已实现 `AckCRC` 匹配：Type、Number、CRC32 都一致才推进状态。
- [ ] 已实现 500 ms 超时与最多 5 次重发。
- [ ] 已实现 `GetCRC`、`GetMID`、`GetSta` 的查询事务收尾。
- [ ] 已实现 1 KB 控制页、15 个程序页、页内 256 块。
- [ ] 已实现页级断点记录和恢复。
- [ ] 已确认升级后设备返回的是目标区 CRC，查询时返回运行区 CRC。

## 二、CRC 与帧测试

- [ ] 用文档中的 10 条完整 16 字节示例逐条对比 CRC。
- [ ] 将同一帧拆成任意多段喂给接收解析器，不应丢帧。
- [ ] 连续输入两帧，第一帧 `AckCRC` 丢失时第二帧仍可正常处理。
- [ ] 输入错误 Type、错误 Number、错误 CRC、错误页号时分别验证错误路径。
- [ ] 把 Data 中的多字节值按小端构造并回读。

## 三、OTA 流程测试

- [ ] 15 页均与运行区相同：只发控制页，不发送程序页。
- [ ] 仅第 0 页不同：控制页后只发送 Page0 的 256 帧。
- [ ] 多个不同页：严格按升序发送。
- [ ] 写第 N 页过程中断开：重连后从 N 页继续，已完成页不重发。
- [ ] 控制页 CRC 错误：设备拒绝并报告 `CONTROL_PAGE_INVALID`。
- [ ] 页 CRC 错：设备报告 `PAGE_CRC_MISMATCH`，不报告升级成功。
- [ ] 最后 `SetEnd` 成功后收到完整 1+16+1+1 回报序列。
- [ ] 最终 `SetCRC` 的 Number 与目标页一一对应。
- [ ] 失败时收到 `SetEro`，且最终 `SetEnd` 的 Error_code 非 0。

## 四、链路测试

- [ ] USART2 115200 8N1 下连续传输 1 KB 控制页。
- [ ] SI24R1 配置动态负载 16 字节时逐帧收发。
- [ ] 模拟 500 ms、1 s、5 s 延迟和连续丢包。
- [ ] 检查 PC 端不会因重复 ACK 或迟到 ACK 重复推进块号。
