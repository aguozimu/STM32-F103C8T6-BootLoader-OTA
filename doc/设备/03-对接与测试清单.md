# 设备对接与测试清单

> 协议版本：`OTA-PROTO-1.0`　完整规范：`01-通讯协议完整规范.md`

## 一、接收与 ACK

- [ ] USART2 使用 `0xA5` 搜索和固定 16 字节滑窗，不按 UART 空闲中断直接切帧。
- [ ] 对 16 字节帧计算 STM32F1 硬件 CRC，结果与 PC 算法一致。
- [ ] 业务帧 CRC 正确后回 `AckCRC`，Number 和 CRC 原值正确。
- [ ] `AckCRC` 自身不再回复。
- [ ] 重复帧只重发 ACK，不重复擦写 Flash。
- [ ] 语义错误时先确认业务帧，再发 `SetEro`。
- [ ] 等待确认 500 ms，最多重发 5 次。

## 二、控制页与选槽

- [ ] 控制页固定 1 KB，前 132 字节字段和偏移正确。
- [ ] Page_ADD 来自相对地址，设备按所选槽基址换算。
- [ ] Page16.CRC 计算前把自身 4 字节字段置 0。
- [ ] 控制页自身 CRC 错误时不选槽、不写 Flash。
- [ ] 一号运行区不被覆盖。
- [ ] 二/三号区中保留最新 `VALID_BACKUP`。
- [ ] 两个有效槽按 16 位回绕规则选择较旧槽。
- [ ] 相同 ID/状态无法区分时选择二号槽。
- [ ] `PAUSED` 且 ID 相同的槽优先续传。

## 三、逐页写入

- [ ] 每个程序页收满 256 个连续 `SetDat` 后才允许写 Flash。
- [ ] 块号从 0 连续到 255，重复块只重发 ACK。
- [ ] 擦除失败、写入失败、页 CRC 不一致分别返回正确错误码。
- [ ] 写成功后更新该页 CRC、`Data_area`、Page16.CRC 和整张控制页。
- [ ] 未完成页 CRC 清零，不允许残留旧 CRC。
- [ ] 15 页都完成后才进入 `VERIFYING`。
- [ ] 最终 `SetCRC` 返回目标区 16 页 CRC，而不是运行区 CRC。

## 四、最终握手与恢复

- [ ] 成功时依次发 `SetMID`、16 帧 `SetCRC`、`SetSta`、`SetEnd`。
- [ ] 每个非 `AckCRC` 帧都等待上位机确认。
- [ ] 成功最终状态为 `0x05 / FF / FF / 00`。
- [ ] 失败最终状态为 `0x07`，错误码非 0。
- [ ] 断线后状态变为 `0x03`，已确认页保留、未完成页清零。
- [ ] 重新发送控制页后可从最小待写页继续。

## 五、Flash 场景测试

- [ ] 目标槽为空、只有有效备份、两个有效备份、两个无效槽。
- [ ] 页擦除后断电，再上电可识别为未完成。
- [ ] 写到一半断电，重新上电不会误判升级成功。
- [ ] 控制页更新过程中断电，旧版本仍可作为备份。
- [ ] ID 从 `0xFFFF` 回绕到 `0x0001` 时新旧比较正确。
- [ ] 所有 15 页相同，允许只更新控制页并正常结束。
